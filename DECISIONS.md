# Decisions

v0.1 choices, each with the reason it was made. Limits that follow from those choices are at the bottom.

- **python-telegram-bot (v21, long polling).** One process, no webhook, and no inbound port to open on the VPS.
- **httpx.** Async, and `MockTransport` lets the tests fake every vendor without another library.
- **Three sources run together under one timeout each.** A slow Safe Browsing call must not delay the VirusTotal and URLhaus lines.
- **Missing API key skips that source and says so.** A half-configured `.env` should still answer, not crash on startup.
- **Grok is the judge, behind a `Judge` interface.** The verdict sentence is the part worth a model. The interface is where an open-source model, then OpenAI, will slot in later. Those backups are not built.
- **Rules judge if xAI fails, is unconfigured, or disagrees with the table.** The bot still owes a verdict when the model is down. A positive or suspicious hit is not waved through, and a missing or failed source does not turn a clean result into CAUTION.
- **xAI via `POST https://api.x.ai/v1/chat/completions`, model `grok-4.7`.** That is the OpenAI-compatible base URL the project asked for. `XAI_MODEL` overrides the id when xAI renames it. Chat completions is the legacy endpoint; newer xAI features land on the Responses API first.
- **Safe Browsing v4 `threatMatches.find`.** It is the lookup API: we send the URL, they say whether it is on a list. Empty body means clean.
- **VirusTotal lookup first, then a scan when the URL is new.** The first reply stays fast. A missing report is submitted with `POST /api/v3/urls` and polled for about 60 seconds, and the result arrives as a second message. All VirusTotal calls share a budget of 4 per minute, which is the public free tier.
- **VirusTotal malicious means any engine (`malicious >= 1`).** Simple and conservative. It will sometimes false-positive.
- **URLhaus `POST /v1/url/` with the `Auth-Key` header.** That is the documented single-URL lookup. Being listed is malicious even if the URL is offline; `no_results` is clean because the feed only contains malware URLs.
- **Allowlist, and silence for everyone else.** A private checker should not explain itself to strangers or confirm the bot is alive.
- **Private chats only.** The same silence applies in groups, so a pasted link in a group is not answered out loud.
- **Secrets only from the environment.** `.env.example` has blanks, `.env` is gitignored. Source failures log the HTTP status and, for URLhaus, `query_status`, never the API key or the request URL (Safe Browsing puts its key in the query string).
- **SQLite, one table, 90-day cleanup, `archive` exempts a row.** The history is small. `/archive` is the only way to set the flag. There is no un-archive command. The daily loop starts in `Application.start`, after the bot is running. `create_task` during `post_init` is too early: python-telegram-bot warns and does not track the task. Shutdown sets an event so the loop exits instead of sleeping out the rest of the day.
- **At most three items per message.** Links are taken first, then email addresses, then phone numbers. One paste should not fan out into dozens of vendor calls.
- **Email checks need no new paid key.** Syntax, MX/SPF/DMARC, RDAP domain age (IANA bootstrap), a vendored disposable-domain list, and a small brand lookalike list all run without a key. Safe Browsing, VirusTotal, and URLhaus then run against `https://<domain>/` and share the existing VirusTotal budget of 4 requests a minute, including the follow-up scan. The follow-up submits the domain, not the mailbox.
- **Missing MX is suspicious. Missing SPF or DMARC is only reported.** A lot of real domains still have no SPF or DMARC. No MX means the domain does not accept mail.
- **A domain under 30 days old is suspicious.** Age comes from RDAP. A missing registration date is "unknown", which does not by itself block GO when another source is clean.
- **Disposable domains are suspicious, and brand lookalikes are malicious.** Neither can come back GO. The disposable list is the normal-mode snapshot from github.com/disposable/disposable-email-domains (generated by github.com/disposable/disposable), fetched 2026-11-18, not the strict list, so ordinary freemail is not flagged. The lookalike list is PayPal, Apple, Microsoft, Amazon, Google, a handful of US banks, and the big shippers. Short names are not fuzzy-matched, because one edit flags ordinary words.
- **Phone checks are offline unless Numverify is configured.** libphonenumber supplies validity, region, and line type from prefix data shipped with the library. That is not a live carrier lookup, and the reply says so. Premium-rate, shared-cost, VoIP, and invalid numbers are suspicious. `NUMVERIFY_API_KEY` adds a live carrier and line type and is skipped when blank, like the other keys. The number is sent to Numverify only in that case. Have I Been Pwned is not queried.
- **National phone numbers use `DEFAULT_PHONE_REGION` (default US) and must be valid.** A number with a country code is read as that country. Invalid numbers are not extracted.
- **Email addresses and phone numbers are not stored or logged in full.** The row keeps a subject type, the SHA-256 of the canonical form (lowercased email, or E.164), and a redacted display form (`j***@paypal.com`, `+1******2671`). The raw value is scrubbed out of source text before it is judged or saved. An existing database gains the new columns with `ALTER TABLE`, which keeps the old rows. Cleanup and `/archive` are unchanged.
- **Defang support is `hxxp`/`hxxps`, `[.]`, `(.)`, `{.}`, `[dot]`, `(dot)`, `[:]`, and `[at]` / `(at)` for email.** Those are the forms people actually paste. Userinfo (`user:password@host`) is stripped so a credential in a URL is not stored, and that address is not also checked as an email.
- **The container runs as uid 1000 and stores the database on a named volume.** A named volume picks up that ownership, so `docker compose up` can write the sqlite file without a host-side `chown`. The image publishes no ports.
- **Official `python:3.12-slim` image, compose on Ubuntu 24.04.** The VPS does not need its own Python; the image has 3.12.
- **Ruff and pytest in GitHub Actions on every push and pull request.** The tests never call the network. DNS and RDAP are fixtures.

## Known limits

- No live call to Telegram, xAI, the vendors, DNS, or RDAP is part of CI. The request shapes are tested against mocks.
- A brand-new URL that VirusTotal has not scanned is GO when another configured source is clean, and CAUTION when nothing came back clean. The same rule applies to an email domain.
- Bare IP addresses, `localhost`, and internationalized domains are not extracted. `http://1.2.3.4/...` is, because it has a scheme.
- Filenames such as `notes.txt` are not treated as links. A real site whose suffix is in that small denylist (`txt`, `pdf`, `py`, ...) and that was pasted with no scheme is also skipped.
- Redirects are not followed by this bot. The vendors may follow them on their side. RDAP requests do follow redirects.
- Grok is instructed to follow the same verdict table as the rules, and to say "this email" or "this phone number" when that is what was checked. If it disagrees with the table, the rules verdict is the one that is sent.
- VirusTotal is limited to 4 requests a minute, shared by link checks and email-domain checks. The other sources are limited by the allowlist and the three-item cap.
- A phone line type is offline prefix data. It will be wrong sometimes, and it is not the carrier. Numverify is the only live phone source, and only when the key is set.
- `DEFAULT_PHONE_REGION` misreads a foreign number written without a country code. `+44 ...` is fine. `020 ...` is only read as London when the region is GB.
- The disposable list is a snapshot and will go stale. It can also false-positive. Subdomains of a listed domain are treated as listed.
- The lookalike list is small. `paypal.co.uk` is called a lookalike of `paypal.com` even if the company owns it. `apple` and `ups` are not fuzzy-matched. `apply.com` is not flagged.
- Email threat intel checks `https://the-domain/`, not the mailbox. A phish that lives on a path can be missed.
- RDAP dates are the top-level registration event only. Some registries put the date somewhere else; those come back unknown.
- No HIBP, and no live carrier claim from libphonenumber.
- No project license file yet. The vendored disposable list keeps its own MIT notice next to the data file.
